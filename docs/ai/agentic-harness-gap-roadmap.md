## 迭代规则

- 每次只做一个 vertical slice：规则 -> 最小脚本 / hook -> 测试 -> 文档入口 -> 样本证据。
- 真实样本 lane 默认进入 [Harness Real Sample Watchlist](./harness-real-sample-watchlist.md)；不要为了补齐计数制造 synthetic / local-only / placeholder evidence，也不要反复运行 planner / intake / readiness 来追不存在的真实场景。
- 真实事件发生后，再用 `scripts/plan_harness_sample_collection.py` 做 no-write route / review，而不是把队列当成主动待办；队列复用 readiness 计数、pending-slot 覆盖和 target checker command 显示 current / upgrade target、`readiness_metric_delta`（如有）、pending slot status、ledger action、`capture_gate` / `capture_gate_detail` 真实事件前置条件与复核路径，markdown / JSON / capture-card 还会输出 lane-specific review command 字段（`replacement_review_command`、`append_review_command`、`outcome_review_command`、`upgrade_decision_review_command`、`contract_precondition_review_command`），避免消费者只靠 `ledger_action` 或 accepted real row count 推断命令 / readiness 是否满足；`--capture-card` 会展开 pending ledger refs 和 review blockers，ready-gap upgrade decision cards 会显示 `Next evidence needed`，contract-blocked future-work entries 还会展开 `contract_blocker_state` 的 missing ADR refs、sample boundary、next action 和 review command；空过滤范围的 markdown / capture-card 会输出显式 no-match 并成功退出，JSONL 模板空范围保持 stdout 为空，避免把当前无匹配 lane 误读成工具失败或 evidence
