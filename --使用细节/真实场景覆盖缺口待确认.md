# 真实场景覆盖缺口待确认

Updated: 2026-05-10
Scope: agentic harness, eval, trace, security evidence, AI guardrail, workflow skills

## 用途

这份文档只记录当前 harness 已有机制之外，尚缺少真实场景样本或人工确认的点。后续出现真实 PR、scheduled run、跨 workstream、外部互通、MCP/A2A 等场景时，按这里的清单定向补证据。

不要把本文件中的待确认项误判为已完成能力。本文件不是 canonical 项目状态；长期结论仍应提升到 `docs/ai/status/*`、`docs/ai/harness-open-items.md`、ADR、requirements 或 traceability 文档。

## 当前结论

目前可以继续做本地确定性能力：

- eval runner + deterministic grader：可以做，风险低，收益高。
- `agent-trace/v1` 本地 export adapter 与 no-network `otlp-http-json` pilot：可以做；显式 `--send --endpoint` 才能产生本地/远端 HTTP export 证据，但仍不等于 OpenAI hosted trace、MCP 或 A2A。
- security / guardrail / workflow sample collection harness：可以做，用于收集缺口和生成样本检查面。

目前不应声明完成：

- OpenAI exporter、OTLP exporter 的真实后端互通。
- MCP / A2A 的真实工具协议互通。
- security evidence、AI guardrail、workflow skills 在真实 PR / scheduled / 跨 workstream 上的充分覆盖。

## 后续处理规则

1. 有真实场景时，先按上表找到 gap ID 对应的 area，再补最小可审计证据。
2. 样本进入共享 truth 前，先区分 runtime 证据、PR 证据、status 结论、ADR 决策。
3. 远端互通必须单独标明 endpoint、权限、数据脱敏、失败模式和费用边界。
4. 如果只是本地 adapter、dry-run、schema、checker 通过，只能写成 local validation complete。
5. 如果出现跨 workstream 或多人/多 AI PR 冲突，优先补 workflow skill 和 team PR conflict 样本。
